# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Модели данных

#### Catalog
Класс ```Catalog``` отвечает за хранение и управление данными каталога товаров в приложении.
Он хранит список всех товаров, доступных пользователю, а также товар, выбранный для детального просмотра.

##### Зона ответственности
Класс отвечает за:
* хранение массива всех товаров, доступных в каталоге;
* хранение товара, выбранного пользователем для детального просмотра;
* предоставление методов для получения и обновления данных каталога.

```constructor(products: IProduct[] = [])``` 

Параметры:
* ```products: IProduct[]``` — массив товаров, который используется для начальной инициализации каталога. По умолчанию используется пустой массив.

Поля класса:

```private products: IProduct[]```
Хранит массив всех товаров, доступных в каталоге приложения.

```private selectedProduct: IProduct | null = null``` 
Хранит товар, выбранный пользователем для детального просмотра.
Если товар не выбран, значение поля равно null.

Методы класса:

```setProducts(products: IProduct[]): void```
Принимает массив товаров и сохраняет его в модели. Используется для обновления списка товаров в каталоге.

```getProducts(): IProduct[]```
Возвращает массив всех товаров, хранящихся в каталоге.

```getProductById(id: string): IProduct | undefined```
Принимает идентификатор товара и возвращает товар с указанным id.
Если товар с таким идентификатором отсутствует, метод возвращает ```undefined```.

```setSelectedProduct(product: IProduct | null): void```
Сохраняет товар, выбранный пользователем для детального просмотра.
Если товар не выбран, в поле сохраняется ```null```.

```getSelectedProduct(): IProduct | null```
Возвращает товар, выбранный пользователем для детального просмотра.
Если товар не выбран, возвращает ```null```.

#### Cart

Класс ```Cart``` отвечает за хранение и управление товарами, которые пользователь выбрал для покупки. Он хранит список товаров, добавленных в корзину, и предоставляет методы для управления содержимым корзины.

##### Зона ответственности

Класс отвечает за:
 * хранение массива товаров, добавленных пользователем в корзину;
 * добавление и удаление товаров из корзины;
 * очистку корзины;
 * получение списка товаров в корзине;
 * вычисление общей cуммы стоимости товаров;
 * вычисление количества товаров;
 * проверку наличия товара в корзине.

```constructor(products: IProduct[] = [])``` 
 
 Параметры:
* ```products: IProduct[]``` — начальный список товаров в корзине. По умолчанию используется пустой массив.

Поля класса:

```private products: IProduct[]``` Хранит массив товаров, добавленных пользователем в корзину.

Методы класса:

```getProducts(): IProduct[]``` Возвращает массив товаров, находящихся в корзине.

```addProduct(product: IProduct): void``` Принимает товар и добавляет его в массив товаров корзины.


```removeProduct(id: string): void``` Принимает ```id``` товара и удаляет товар с указанным идентификатором из корзины.

```clear(): void``` 
Полностью очищает корзину, удаляя все товары.

```getTotalPrice(): number```
Возвращает суммарную стоимость всех товаров, находящихся в корзине.

```getCount(): number```
Возвращает количество товаров, находящихся в корзине.

```hasProduct(id: string): boolean```
Проверяет наличие товара в корзине по его ```id```.
Возвращает ```true```, если товар присутствует в корзине, иначе ```false```.

#### Buyer

Класс ```Buyer``` отвечает за хранение и управление данными покупателя, введёнными при оформлении заказа.
Он позволяет сохранять, получать, очищать и валидировать персональные данные пользователя.

##### Зона ответственности

Класс отвечает за:

* хранение данных покупателя (вид оплаты, адрес, телефон, email);
* сохранение и обновление как всех данных сразу, так и отдельных полей;
* предоставление полного объекта данных покупателя;
* очистку всей информации о покупателе;
* валидацию данных и формирование отчета об ошибках для каждого поля.

Конструктор:
```constructor(data: Partial<IBuyer> = {})```

Параметры: ```data: Partial<IBuyer>``` — начальные данные покупателя. По умолчанию используется ```{}```.

Поля класса:

```private payment: TPayment``` — выбранный способ оплаты, может быть: `online`, `offline` и `''`

```private address: string``` — адрес доставки товара.

```private email: string``` — электронная почта пользователя.

```private phone: string``` — контактный номер телефона.


Методы класса:

```setData(data: Partial<IBuyer>): void```
Принимает объект с данными покупателя и обновляет соответствующие поля класса. Метод позволяет обновлять как одно, так и несколько полей одновременно, не перезаписывая и не удаляя остальные данные, которые уже хранятся в классе.

```getData(): IBuyer``` Возвращает объект, содержащий все текущие данные покупателя (payment, address, email, phone).

```clear(): void```Полностью очищает данные покупателя, сбрасывая все поля к исходному пустому состоянию.

```validate(): TFormErrors | {}``` Выполняет проверку всех полей класса. Поле считается валидным, если оно не является пустой строкой. Метод возвращает объект с ошибками, где ключ — это название поля, а значение — текст ошибки. Если поле успешно прошло валидацию, оно не включается в результирующий объект. Пустой объект означает, что все данные верны. 

### Слой коммуникации

#### CommunicationApi

Класс ```CommunicationApi``` отвечает за взаимодействие приложения с сервером.
Он используется для получения данных о товарах и отправки данных заказа на сервер.

##### Зона ответственности

Класс отвечает за:
	•	выполнение запросов к API сервера;
	•	получение списка товаров с сервера;
	•	отправку данных заказа (товары + данные покупателя) на сервер;

Конструктор:
```constructor(api: IApi)```

Параметры: `api: IApi` — объект для выполнения HTTP-запросов, реализующий методы `get` и `post`.

Поля класса:

`private api: IApi` — объект `API`, используемый для выполнения запросов к серверу.

Методы класса:
```getProducts(): Promise<TProductsResponse>``` Выполняет `GET` запрос на эндпоинт `/product/` и возвращает объект, полученный от сервера, в котором находится массив товаров.

```sendOrder(order: TOrderRequest): Promise<TOrderResponse>```
Выполняет `POST` запрос на эндпоинт `/order/` и передаёт в него данные, полученные в параметрах метода, а возвращает объект, подтверждающий покупку на определенную сумму.

#### Modal
Класс `Modal` отвечает за отрисовку и управление модальным окном. Не может иметь дочерних классов — всё содержимое передаётся как самостоятельные компоненты. Наследуется от класса `Component`.

##### Зона ответственности
Класс отвечает за:открытие и закрытие модального окна;
отображение переданного контента внутри модального окна;
генерацию события закрытия при клике на крестик или на оверлей.

Конструктор:
`constructor(container: HTMLElement, events: IEvents)` принимает ссылку на DOM элемент модального окна и брокер событий.

Поля класса:

`protected _content: HTMLElement` элемент содержащий контент модального окна.
`protected _closeButton: HTMLButtonElement` кнопка закрытия модального окна.

Методы класса:

`set content(value: HTMLElement)` устанавливает контент внутри модального окна.
`open(): void ` открывает модальное окно добавляя модификатор `modal_active`.
`close(): void ` закрывает модальное окно удаляя модификатор `modal_active`.

### События

#### Данные
`catalog:changed` — обновление каталога товаров
`preview:changed` — изменение выбранного товара
`cart:changed` — изменение корзины
`buyer:changed` — изменение данных покупателя

#### Карточки
`card:select` — выбор карточки товара
`card:toggleCart` — добавить/удалить товар из корзины
`card:remove` — удаление товара из корзины

#### Корзина и заказ
`basket:open` — открыть корзину
`order:open` — открыть форму заказа

#### Форма заказа
`order:input` — изменение данных заказа (адрес, оплата)
`order:submit` — переход к форме контактов

#### Контакты
`contacts:input` — изменение email/телефона
`contacts:submit` — отправка заказа

#### Подтверждение заказа
`success:close` — закрытие экрана успешного заказа

#### Модальное окно
`modal:close` — закрытие модального окна

#### Презентер
Презентер реализован в `main.ts` и является центральным слоем приложения, который координирует взаимодействие между моделями и представлением через событийную систему (`EventEmitter`).

Презентер отвечает за:
- подписку на события, генерируемые моделями и компонентами представления;
- обработку пользовательских действий (клики, ввод данных, отправка форм);
- обновление состояния моделей на основе событий;
- передачу актуальных данных в компоненты представления для их перерисовки;
- управление отображением модальных окон и последовательностью шагов оформления заказа;
- взаимодействие с API (получение товаров и отправка заказа).

Таким образом, презентер выступает в роли посредника, который координирует работу всех частей приложения и обеспечивает целостность логики.
